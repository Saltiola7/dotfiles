# Controlled editor preparation recovery (RRW-007I / INT-085)

## Domain and ownership

The owner overlay prepares the committed AstroNvim configuration, exact Lazy lock
and ten required parsers. The foundation owns its disjoint runtime targets. Fork A
owns all live rollout and the existing VM's separately reviewed one-time repair.
Build qualifies disposable installations only. No lock/version pins, public setup
inputs, foundation bootstrap or macOS/lmsh behavior change.

An **attempt** is an exclusively serialized preparation in a helper-private plugin
generation. A **seal** records its exact bounded inventory after native execution
has stopped. **Readiness** means successful locked restore, actual required parser
build/load verification and real owner startup at the final normal plugin path.
Attempt provenance is not readiness and Git history is not authorship evidence.

## Evidence and approved boundary

An isolated pinned-version reproduction produced generated `doc/tags` after a
deliberate parser failure; the helper previously wrote their receipts only after
all stages passed. Fork A's corrected legacy evidence found newer clone-tip HEADs
and deletions equal to paths added between the lock and those tips: consistent with
checkout interrupted after removing newer files but before moving HEAD. This
corrects the initial blob-materialization hypothesis; set equality is diagnostic
evidence only, not a recovery authorization. The exact event is not reproduced here.
A genuine local deletion can also have a clone-only reflog, index equal to locked
HEAD, promisor configuration, no modifications and a missing path present in HEAD.
These facts never authorize automatic in-place repair.

The approved split is therefore:

- Future controlled failures resume using durable setup provenance and isolated
  candidates. Never repair ambiguous worktrees by shape or deleted-path whitelist.
- Existing unreceipted legacy dirt stays untouched and refuses automatic setup.
  Fork A's attestation and exact public path list inform a separate one-time
  operator-reviewed repair, not a permanent relaxation of dirty-state protection.

Fork A reports that one-time repair completed: 45/45 plugins clean at the lock,
overlay apply succeeded and ten parsers verified. This is operator-reported live
evidence, separate from Build's disposable qualification. The VM is no longer a
reproduction target; Build does not repeat or undo that repair.

Helper-private staging is an operational boundary, not a security boundary against
a malicious same-UID actor. Installer serialization excludes other setup processes,
not manual edits or editors. Ordinary startup never selects a failed candidate.
Post-seal changes must refuse, and the current normal root must be revalidated before
promotion. Do not claim hashes establish authorship of concurrent same-user writes.

## Behavior and interfaces

Given missing readiness and a safe absent or validated clean normal plugin root,
persist an attempt before native work and restore into a new private candidate.
Use helper-controlled root selection during preparation only; normal startup keeps
its ordinary plugin path. The managed owner lock remains byte-identical.

Given a controlled native failure and stable, safely bounded candidate inventory,
seal it without publishing readiness. On the next apply, require the same lock,
unchanged normal-root preimage and exact seal. Retain that failed candidate unchanged
and prepare a fresh generation from the same pins. Never reset, clean, fill missing
tracked files or delete partial plugin trees to manufacture success.

Given changed candidate files, extra files, stale/invalid provenance, unsafe links,
hardlinks, exhausted bounds or abrupt death before a trustworthy seal, retain all
state and refuse for review. Genuine tracked edits/deletions and untracked work in
the normal root remain refusals both before preparation and before promotion.

Given a fully verified candidate, journal promotion before any rename. Retain the
old validated root rather than deleting it; select the candidate at the normal root
only under an unambiguous expected layout. Two renames are not an atomic root swap.
On interruption, reconcile exact inventories and location facts; refuse ambiguity.
Require a normal-path owner startup and final plugin/parser/lock checks before
publishing readiness last. A failed final startup may resume only while its recorded
state still matches. Reapply against valid existing readiness remains idempotent.

Use the existing private editor state owner for versioned attempt records, retained
generations and the exclusive setup lock. Files are owned, regular, single-link,
mode 0600; directories are private. Validate ancestry/no-follow access and finite
file/count/byte/path limits, reject duplicate JSON keys and unsupported schemas,
and publish atomically with file and directory durability. Reject cross-device
promotion rather than silently copying or falling back. Retention is bounded;
capacity exhaustion requires operator review, never automatic garbage collection.

No new CLI options or TOML keys are introduced. Root selection is internal to the
controlled helper and Lua invocation; it is not a user-controlled recovery bypass.
Keep native output private and emit fixed bounded failure stages/reasons only.
Rollback removes only existing overlay-owned managed targets and retains user data,
failed attempts and prior plugin generations. No live remediation is performed.

## Validation and maintenance

Tests cover generated tags, parser and second-start failures, sealed retry, normal
reapply, preexisting dirty roots, genuine edits/deletions after failure, changed
locks, invalid/unsafe seals, lock contention, abrupt incomplete attempts and every
promotion boundary. Assert byte preservation of failed/previous roots and missing
readiness until full success. Keep the native Git-shape counterexample.

Qualify the full configured pytest population and affected Python 3.12 analysis,
isolated chezmoi rendering/overlap, and native UBI10 paired failure/retry against
the merged foundation revision recorded at cycle registration. Build/load all ten
parsers and dependencies, verify a second real startup, reapply and rollback
without changing foundation hashes. macOS reproduction is diagnosis, not
RHEL/parser acceptance.
Do not substitute Lua stubs for native acceptance. Add the Lua contract harness to
workflow path selection if changed. Current results and retained failures belong
in the Cycle Record. Merge needs separate final exact-head approval.
